# میل‌باکس — ساخت و مدیریت ایمیل موقت

یک پروژه آماده استقرار با رابط فارسی برای ساخت آدرس ایمیل موقت، ذخیره اطلاعات آن و مشاهده پیام‌های دریافتی؛ بدون نیاز به دامنه شخصی. ارائه‌دهنده ایمیل [mail.tm](https://mail.tm/) است و برنامه از [API آن](https://docs.mail.tm/) استفاده می‌کند.

## امکانات و محدودیت‌ها

- ساخت آدرس روی دامنه فعال سرویس؛ انتخاب نام دلخواه یا ساخت خودکار نام بر پایهٔ ترکیب نام و نام‌خانوادگی واقعی (فینگلیش و بین‌المللی) مانند `ali.ahmadi` یا `emma.walker42`. اگر نام ساخته‌شده قبلاً در سرویس گرفته شده باشد، برنامه به‌طور خودکار نام دیگری امتحان می‌کند.
- ذخیره آدرس، تاریخ ایجاد و رمز تصادفی حساب در SQLite. رمزها با کلید مشتق‌شده از `APP_SECRET` رمزگذاری می‌شوند.
- مشاهده فهرست پیام‌ها و متن پیام، نمایش رمز حساب و کپی آدرس؛ حذف حساب از **فهرست محلی** (نه از سرویس ایمیل).
- ورود به پنل با رمز مدیریت؛ این پروژه یک پنل تک‌کاربره است و برای سرویس عمومی و چندکاربره طراحی نشده است.
- پیام‌ها فقط هنگام مشاهده از mail.tm دریافت می‌شوند و در پایگاه داده برنامه ذخیره نمی‌شوند. پشتیبانی از ارسال ایمیل، پیوست و نمایش کامل HTML وجود ندارد؛ HTML فقط به متن تبدیل می‌شود.
- **ایمیل‌ها موقت‌اند** و ممکن است ارائه‌دهنده بدون اطلاع حذف یا منقضی کند. بعضی سایت‌ها ایمیل موقت را نمی‌پذیرند. از آن برای حساب‌های مهم یا بازیابی رمز استفاده نکنید. ذخیره رمز در برنامه به معنی ماندگاری حساب یا پیام‌ها نزد ارائه‌دهنده نیست. این پروژه Gmail نمی‌سازد.
- سرویس ممکن است محدودیت نرخ، از جمله برای ساخت ایمیل، اعمال کند. در صورت خطای 429 کمی صبر کنید؛ عملکرد و دسترسی به سرویس وابسته به mail.tm است.

## استقرار در Railway از طریق GitHub

1. یک مخزن جدید در GitHub بسازید و **محتویات همین پوشه** را در ریشه آن آپلود کنید؛ فایل‌های `Dockerfile` و `railway.json` باید در ریشه مخزن باشند. اطلاعات محرمانه را داخل مخزن نگذارید. برای استفاده شخصی بهتر است مخزن خصوصی باشد.
2. در Railway یک پروژه جدید بسازید، گزینه **Deploy from GitHub repo** را انتخاب کنید و مخزن را به آن وصل کنید. اتصال ممکن است از شما مجوز GitHub بخواهد.
3. در تنظیمات سرویس، بخش **Variables**، مقادیر زیر را وارد کنید:

   | متغیر | مقدار |
   |---|---|
   | `ADMIN_PASSWORD` | یک رمز قوی، حداقل ۱۲ کاراکتر؛ برای ورود به پنل |
   | `APP_SECRET` | یک رشته تصادفی محرمانه و ثابت، حداقل ۳۲ کاراکتر |
   | `DATA_DIR` | `/data` |

   مثلاً با دستور زیر روی کامپیوتر خودتان یک مقدار برای `APP_SECRET` تولید کنید و خروجی را فقط در متغیر Railway قرار دهید:

   ```bash
   python -c "import secrets; print(secrets.token_urlsafe(48))"
   ```

   **`APP_SECRET` را پس از ساخت ایمیل‌ها تغییر ندهید**: تغییر آن رمزهای ذخیره‌شده را غیرقابل‌بازیابی می‌کند و نشست‌ها را خارج می‌کند. از آن و رمز مدیریت در محل امن و جدا از GitHub نسخه پشتیبان داشته باشید. اگر کلید درز کند، رمز حساب‌ها قابل رمزگشایی است. در صورت از دست رفتن کلید، اگر رمزها را جداگانه نگه نداشته باشید، دیگر قابل بازیابی نیستند.
4. به همین سرویس یک **Volume** اضافه کنید و مسیر Mount را دقیقاً `/data` قرار دهید؛ سپس سرویس را مجدداً Deploy کنید. پایگاه داده در `/data/mailboxes.sqlite3` ایجاد می‌شود. بدون Volume اطلاعات محلی ممکن است با استقرار مجدد یا ری‌استارت از بین بروند. اگر Volume را پس از ساخت آدرس‌ها اضافه کنید، داده‌های قبلی به‌صورت خودکار منتقل نمی‌شوند؛ پیش از ساخت آدرس Volume را وصل کنید.
5. در تنظیمات **Networking** گزینه **Generate Domain** را بزنید. آدرس HTTPS ارائه‌شده را باز و با `ADMIN_PASSWORD` وارد شوید. Railway متغیر `PORT` را تعیین می‌کند؛ نیازی به تنظیم دستی آن نیست.
6. از Volume به‌طور جداگانه پشتیبان بگیرید. Volume جایگزین بکاپ نیست. سرویس را با **یک replica** اجرا کنید؛ SQLite و محدودکننده ورود این نسخه برای چند replica طراحی نشده‌اند.

هزینه، اعتبار رایگان، دسترسی به Volume و شرایط Railway ممکن است تغییر کنند؛ قبل از استقرار در پنل Railway بررسی کنید. اگر برنامه به دلیل نبود متغیرها بالا نیامد، آن‌ها را در Variables ثبت و دوباره Deploy کنید. اگر ساخت یا خواندن ایمیل خطا داد، وضعیت mail.tm و محدودیت‌های آن را بررسی کنید.

## اجرای محلی

Python 3.10 یا جدیدتر لازم است:

```bash
python -m venv .venv
# Linux / macOS:
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
export ADMIN_PASSWORD='a-long-unique-admin-password'
export APP_SECRET='a-long-random-secret-at-least-32-characters'
python app.py
```

در PowerShell به جای `export` از `$env:ADMIN_PASSWORD="..."` و `$env:APP_SECRET="..."` استفاده کنید. سپس `http://localhost:8080` را باز کنید. داده‌های محلی به‌صورت پیش‌فرض در پوشه `data` ذخیره می‌شوند. برای HTTPS خارج از Railway، `COOKIE_SECURE=1` را تنظیم کنید. برای اینترنت عمومی حتماً از HTTPS، رمز قدرتمند و یک replica استفاده کنید. محدودکننده تلاش ورود ساده و در حافظه همان پردازه است و جایگزین سامانه احراز هویت حرفه‌ای یا rate limiting در لایه شبکه نیست.

## ساختار

`app.py`: سرور، API و پایگاه داده؛ `templates/` و `static/`: رابط کاربری؛ `Dockerfile` و `railway.json`: تنظیمات استقرار؛ `tests/`: آزمون‌های مستقل از سرویس خارجی.
